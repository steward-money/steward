# Claims

Each promise in Steward's docs, and what proves it. A doc cites a row by its ID, linked to its anchor here. `tests/test_claims.py` fails when a doc cites an ID with no row, a proof doesn't exist, a bullet in the README's "Secure, Private, Thoughtful" section has no ID, or a proven row isn't cited anywhere.

- **Proof:** a path; `file.py::test_name`; or `file.spec.ts::its title`.
- **Kind:** `test`, `file` (the code itself) or `review` (a public summary in `docs/reviews/`).
- **Status:** `proven`, or `pending (PR n)` while its proof is being built. The release gate, `pytest tests/test_claims.py --release`, fails while any row is pending. `, internal` marks a row no doc cites. A doc cites a pending row as planned, its link followed by `(planned)`.

## The name model's eval

P4 and P11 rest partly on the model your gateway runs. Their other proofs use stand-in detectors, so they also cite `tests/gateway/test_models_eval.py`, which runs the real model over the committed question set. The default test run leaves it out because it needs the models group: `uv sync --group models && uv run pytest -q -m models tests/gateway/test_models_eval.py`. The 0.1.0 release gate ran `tests/gateway/test_models_eval.py` on 2026-11-10 at `e49a366`: 3 passed. A pass on a fixed set doesn't prove the model finds every name, which is why both rows say it can miss one.
