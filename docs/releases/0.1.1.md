## What's new

Fixes for the 35 issues the 0.1.0 release gate filed, and two security patches.

### Security

- Wrong passwords lock only the device they come from. A device that has signed in is never locked out by someone else's tries, and a lock answers exactly like a wrong password.
- The API answers only at Steward's own host names. `STEWARD_ALLOWED_HOSTS` adds more.
- `STEWARD_ENV` accepts only `prod`, `test` and `demo`.
- Trusted Types, a permissions policy, X-Frame-Options, CSP reports, and a `__Host-` session cookie on https installs.
- The PDF reader's file wall now allows only fonts and character maps.
- Passkeys can be picked from the username box, and a removed passkey is forgotten by the device.
- The upgrade guide verifies with cosign 3 and pulls by digest.

### Privacy

- A person paid by Zelle, a wire, a transfer or a payment app goes to Claude as `[name]` in an approved store row, unless the manager ticks that row. [Privacy](https://github.com/steward-money/steward/blob/v0.1.1/docs/explanations/privacy.md#which-store-rows-hide-a-name) lists the exact words.
- The exact pass matches more of the names, addresses and birth dates Steward holds.
- Settings > Chat shows the fixed instructions behind the sent log's hash.
- Ollama runs off the internet except to pull a model.
- The proxy's log drops the install's address, and the net-worth milestone is kept per person and cleared at sign-out.

### Thoughtfulness

- Home says what it knows about stale accounts, the saved plan's age, and which month is sorted.
- Clearer recovery and setup pages, a reason when imported rows wait, and the demo opens on Home.
- Screen readers hear one heading per screen and live regions that announce. Home no longer shifts as it loads, and text follows the phone's size setting.

## Before you upgrade

- If you open Steward by more than one name, such as a second VPN name or the address in the gateway's `nas_url`, add the others to `STEWARD_ALLOWED_HOSTS` in `.env` first. At any other name the API answers 421. See [configuration](https://github.com/steward-money/steward/blob/v0.1.1/docs/reference/configuration.md).
- Devices that signed in before 0.1.1 count as new devices for the lockout until they sign in once more. Nobody is signed out.
- Ollama models are now pulled with `docker compose run --rm ollama-pull <model>`.
- A GPU gateway builds from your clone, so run `git pull` there and rebuild it, as the [upgrade guide](https://github.com/steward-money/steward/blob/v0.1.1/docs/guides/upgrade.md) says in step 2.

## Verify the images

Install cosign 3 or newer, and jq. Cosign 2 can't read these signatures. Then check each image against the release workflow's identity:

```
cosign verify ghcr.io/steward-money/steward:0.1.1 \
  --certificate-identity-regexp '^https://github\.com/steward-money/steward/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  | jq -r '.[0].critical.image."docker-manifest-digest"'
```

It prints a digest only when the check passes. Run it again with `steward-proxy` and `steward-gateway` in place of `steward`. The release's digests are listed below, and the [upgrade guide](https://github.com/steward-money/steward/blob/v0.1.1/docs/guides/upgrade.md#verify-the-images) shows how to pull by digest.
